## Search results are for people. Brave’s LLM Context endpoint is for machines.

A results page gives titles and snippets. Agents need parsed data, pre-formatted and pre-filtered for answers.

Brave’s LLM Context delivers just that: The best passages from the best pages, ranked in a single call.

*   ### Every kind of content

Text. Tables. Code. JSON. Forum threads. Video captions. 
*   ### Configure your search

Set from 1k to ~33k tokens. Get just the context you need. 
*   ### Only what's relevant

Pick a threshold: strict, balanced, or lenient. Noise stays out. 
*   ### Fresh and traceable

Every source carries URL & timestamp. Filter to the last 24 hours, and get metadata to see last fetch. 
*   ### Your sources, your rules

Use Goggles to choose which sites ground your model. 
*   ### Local, too

Location-aware results, with places and map data.

## FAQs

 Does Brave ever use Google or Bing results? 

No. Every result comes from Brave’s own independent index, crawled and ranked by Brave. There is no fallback to another search engine for any query.

 Why do you ask for a credit card? 

To prevent abuse. Brave uses prepaid credits, not subscriptions, so you’re only charged for credits you choose to buy.

 How is Brave’s Zero Data Retention different? 

Most ZDR is a contractual promise that can only cover queries the vendor answers itself. Brave’s ZDR is architectural: every query ends on infrastructure we operate end to end, so there’s no third party to retain it.

 Can I store results or use them to train models? 

Yes, with a [plan](https://api-dashboard.search.brave.com/documentation/pricing) that includes storage rights.

 Where does Brave’s data come from? 

Brave’s own web crawler, plus privacy-preserving signals from Brave users who opt in to the [Web Discovery Project](https://support.brave.app/hc/en-us/articles/4409406835469-What-is-the-Web-Discovery-Project). Its code is open source, so anyone can audit it.

## The Brave Search API story

### Answer quality _is_ index quality

To generate great answers, agents need machine-readable data from a global-scale, real-time index of the Web. Google and Bing have shut down their services; needle tests prove all other services scrape (even those claiming not to). This violates Google’s ToS, and returns low-quality, token-inefficient data built for humans. Blue links can’t train AI; scraping is too risky for critical infrastructure like Web search.

Brave is the only fully-fledged search index available through an open API, and it’s the only index built by signals from 130+ million real humans. These anonymous clicks and queries (via Brave browser and Brave Search) help combat AI slop and SEO spam. Indexing 99.9% of the web that matters, Brave has the data agents need, how and when they need it.

Brave’s LLM Context API returns pre-extracted, relevance-scored content chunks (text, tables, code) optimized for machine consumption, eliminating the need for separate scraping and parsing steps. This data-first approach reduces latency to under 500ms at P90, cuts token usage by up to 4x, and provides higher-quality grounding data that helps agents generate more accurate responses with fewer hallucinations on fewer calls.

Brave offers low CPM, high throughput, and high uptime. Structural ZDR vs contractual. SOC2 Type II attestation and regular security audits. Endpoints across LLM grounding (agent search); web search for humans; news, images, video, and places; and even pre-built answers. 3rd-party verified as having the highest agent quality and lowest latency of any provider, Brave is the choice to power your AI.
